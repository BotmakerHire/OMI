01 · Diagnóstico

El bot actual informa. El bot nuevo resuelve.

Hoy el bot funciona como un IVR jerárquico sobre Botmaker: el colaborador entra, navega 2 o 3 niveles de menú, y termina leyendo información estática. La IA participa solo como router entre cajitas. La nueva base de conocimiento (24 temas con sub-temas, palabras clave, contactos, plazos) hace inviable mantener este modelo: significaría 50+ nodos nuevos.

▲ Actual
Árbol de menú estático
  • 9 ramas paralelas con estructura repetida (Variable → Opciones → Mensaje)
  • IA usada como clasificador de menú — costosa y poco útil
  • Información plana: el usuario lee, no resuelve
  • Una única transacción real (turnos de vacunación)
  • Agregar contenido = agregar cajitas. No escala.
  • Sin captura de intención ni métricas de uso real
▼ Propuesta ATS
Agente conversacional con capa transaccional
  • Un agente IA con RAG sobre base de conocimiento estructurada
  • IA usada donde aporta valor (comprensión + respuesta)
  • Lógica determinística para transacciones (sin desperdicio de tokens)
  • 7 transacciones nuevas conectadas a sistemas reales
  • Escalable: nuevo contenido = nuevo registro en base, no nuevo flow
  • Métricas de intent automáticas para mejora continua

03 · Arquitectura

Tres capas, responsabilidades claras.

En lugar de un árbol gigante con lógica mezclada, separamos en capas. Cada una hace una cosa bien. La IA actúa donde aporta valor; lo determinístico se mantiene determinístico. Todo orquestado sobre Botmaker, la plataforma que ya usa Omint.

01
Agente conversacional
El cerebro. Recibe lenguaje natural, entiende el intent, consulta la base de conocimiento vía RAG y responde. Resuelve el 80% de las consultas informativas sin tocar ningún sub-flow.
